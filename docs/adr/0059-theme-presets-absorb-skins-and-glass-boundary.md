# ADR 0059：主题预设吸收「皮肤」，并把透明边界收成跨主题不变量

- 状态：已实施（2026-10-27，用户确认推荐方案后落地）
- 影响面：双端前端（`wasmnest-desktop/src/shell/**`、`wasmnest-mobile/src/shell/**`）、
  双端设置页、i18n、四条样式锁

## 背景

仓内同时存在三个近义机制，且其中一个的名字被占用：

1. `settings.ui.theme` 存 `light|dark|system`——其实是**深色模式**；
2. `ShellThemeSkin`（桌面）存一套 CSS 变量覆盖，挂在壳根 `.shell-root`；
3. `data-palette` 色板——已裁决归各 wasm-app 自持，宿主不写。

用户要求「通过切换主题更换全局样式，留下扩展接口」，并要一个流行的玻璃风格。
若直接新增 `theme`，设置页会出现两个「主题」，代码里 `theme` 一词指两件事。

同时 `surfaceLadder` 锁记录着 2026-10-20 的裁决：「不是全页玻璃，按背后有什么分档」，
并逐文件禁止授权面使用玻璃 token。玻璃主题与这条裁决正面相撞。

## 裁决

1. **主题吸收皮肤，皮肤一词退役。** 用户心智里只有一个轴：「换主题」。
   `ShellThemeSkin` 的字段形状（`tokens` / `darkTokens`）本就是主题的实现形态，
   没必要留两个同构概念。`skin` → `theme`，作用域从 `.shell-root` 抬到 `<html>`。
2. **术语掰正。** `ui.theme` 在文案里叫「明暗模式」，`data-theme` 才叫「主题」。
   不改字段名（改字段要动 AppConfig 与跨仓契约，收益不抵成本），只固定文案口径。
3. **主题的表达方式分两级。** 内置主题的 token 与结构性规则住 CSS
   （`theme-presets.css`），因为结构规则只有 CSS 能写、且 `data-theme` 静态可生效；
   扩展主题只能注册 token 表与 glyph 表，加不了结构规则。
4. **持久化走 localStorage**，与壁纸同层（壳 UI 偏好不进 AppConfig，引擎面纯净）。
   附带收益：同步可读，首帧可预应用，内置主题零闪变。
5. **透明边界升级为跨主题不变量。** 决策面（授权列表 / 授权弹窗 / 确认弹窗 /
   壳弹窗层）在任何主题下保持实心、不接玻璃；内容面与浮层由主题决定是否玻璃化。
6. **作用域只承诺宿主域。** 应用的配色仍归应用；应用子树会自然继承宿主 token，
   但不做契约保证，也不为玻璃改造应用。

## 后果

- 「皮肤」作为机制名从文档与代码消失；旧 localStorage `skin` 值在读取时折算。
- 桌面 `shell/extensions` 的 `registerThemeSkin` → `registerTheme`（保留 id 校验
  扩展到全部内置主题 id）；移动端首次拥有同形的主题注册表。
- i18n 新增 `shell.settings.themes.*`（桌面）与 `settings.appearance.theme*`（移动），
  桌面消息集按 `i18nDriftLock` 同批同步应用仓 bedcode 副本。
- 新增两条覆盖锁（双端各一）：主题目录与主题样式表必须一一对应；决策面不变量
  与 `--bg-card` 不透明是硬断言。
- 玻璃/硬阴影等结构规则全部写在主题样式表里，**不下沉到组件**——这样
  `surfaceLadder` 对组件文件的断言（卡片不得自带 `backdrop-filter`）继续成立，
  同时主题仍然能玻璃化内容面。
- 已知边界：扩展主题在首帧未注册时回落默认主题，注册完成后纠正（可能闪一次）；
  内置主题无此问题。
- **效果审查后的两条落地口径**（2026-10-27，三宽度 × 明暗 × 四主题实拍 + 像素级
  对比度实测后修）：
  1. **主题底色染色降档，主题色改由环境光承担**——给 `--bg-page` 混 info 蓝会把暖灰的
     `--text-secondary` 拖出 AA（实测页头副标题 4.13:1）。现在浅色档染色 3~4%、
     深色档降一档，主题个性由 `--theme-ambient` 的雾光表达，文字对比度回到 AA 以上。
  2. **预览保真**（口径写进 `docs/frontend.md` §6）：默认主题的预览挂 `.theme-base`
     复用基础档 token（不挂 `data-theme`），主题的结构规则锚在
     `.theme-preview[data-theme='x']`、只作用于代表自己的那张预览——否则当前主题的规则
     会顺着 `<html data-theme>` 漏进「默认」预览，预览就成了当前主题的复制品。
- 玻璃面的镜面高光改**两段式棱线**（顶部亮线 + 底部暗线）：单道棱线在明暗各有一半
  压不住底色（浅色下白线压白卡、深色下暗线压暗卡），等于不存在。

## 备选方案与不采纳的理由

- **把 `data-palette` 抬成全局主题**：色板已裁决归应用，抬回宿主等于推翻既有裁决，
  且只换主色不换材质，满足不了「玻璃风格」。
- **纯数据驱动（全部 `setProperty`，无 CSS 文件）**：表达不了结构规则与选择器，
  且首帧必须等 JS 求值。
- **主题存 Rust AppConfig**：跨仓改契约（能力仓 + 双端 Rust + 默认值），
  而主题没有业务真值，收益只是「多端同步」——当前无此需求。
