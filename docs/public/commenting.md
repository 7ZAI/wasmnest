# 代码注释与命名规范（四仓共享）

> **本文件是 `docs/public/`（四仓通用规范）的组成部分**；各仓 AGENTS.md 引用本文件，不复制。
> 与各仓 AGENTS.md 的硬约束同级别。语言侧细则（Rust 命令面 / 前端组件 / i18n）见各仓对应文档。

## 1. 注释

- 注释解释**为什么**（动机 / 取舍 / 坑），中文书写（技术术语保留英文）。
- **禁止引用内部文档章节**。注释必须自解释——读者只读代码 + 注释就能理解，不得依赖任何外部文档才能读懂。以下引用一律禁止，出现即视为注释不合格：
  - 章节引用：`§x.y`、`§x`（如 `spec §6.1`、`ADR 0032 §6`、`设计 §3.2`、`AGENTS §5.1`）
  - 票据编号：`票 NN`、`票据 NN`、`票 NN 裁决`、`T0X` / `T-NN`（任务号）
  - ADR 编号：`ADR ####`、`ADR-0017`、`ADR 0032` 等（作为注释引用时禁止）
  - issue 编号：`issue NN`、`issue 09`
  - spec 变体：`spec v2`、`spec Decision N`、`spec M4`、`Decision N`
  - 其它内部标签：`Q4 裁决`、`R07`、`不变量 N`、`K6` 等内部文档特有编号
- **例外（保留）**：
  - **外部标准引用**：`RFC 6762 §8.3`、`RFC 7748 §6.1/§6.2` 等公开标准，可以引用。
  - **代码路径坐标**：如 `host_api/auth.rs:329`、`src-tauri/src/plugin/ws.rs`，可作为定位说明。
  - **符号名 / 常量名**：代码中的实际标识符。
- 引用被禁时，**改写成直接描述代码逻辑或动机**——把"票 02 操作拆分"改成"按操作种类拆分"，把"ADR 0036：三域留在核心"改成"三域留在核心"并补足为什么留在核心的理由。
- 改代码必须同步修正相关注释（含路径 / 符号名 / 计数声明 / 版本字面量）。
- 退役面 / 迁移的「墓碑」注释是**设计资产**：说明为什么退役的注释保留，不顺手删除。

## 2. 命名

- 组件 / 类：PascalCase；可组合逻辑：`use` 前缀 camelCase（composable）；普通函数与变量：camelCase / snake_case 随语言惯例。
- 文件名与导出一致；Rust 用 snake_case，模块入口文件与目录同名（`module.rs`），不用 `mod.rs`。
- 命名表达意图，不缩写到不可读；禁止用「临时 / tmp / _copy」等作交付名。
